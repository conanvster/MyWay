# Апдейтер-лаунчер MyWay

26.11.2026. Гравець ставить один раз маленький апдейтер. Далі той сам
тягне клієнт із машини сервера, докачує лише змінене й запускає гру з
потрібною адресою.

```
машина сервера (192.168.1.48)                         гравець
┌──────────────────────────────┐                ┌───────────────────────┐
│ ./run-server.sh … UDP 24565  │◄── гра (ENet) ─┤ MyWay (клієнт)        │
│ ./run-updates.sh  TCP 24600  │◄── HTTP ───────┤ MyWay Updater         │
│   updates/ ← tools/opublikuvaty.sh            │  └ ставить і запускає │
└──────────────────────────────┘                └───────────────────────┘
```

## Власникові: як випустити оновлення

```
tools/zibraty.sh                     # клієнт: build/myway-<дата>-<коміт>/
tools/opublikuvaty.sh                # → updates/ (найновіша збірка, усі її платформи)
./run-updates.sh                     # сервіс оновлень, TCP 24600 (лишається працювати)
```

- Назва сервера і порт гри: `tools/opublikuvaty.sh --name "MyWay · дім" --game-port 24565`.
  Їх запам'ятовує `updates/config.json`, тож наступного разу вказувати не треба.
- Кожна нова версія збірки («коміт · дата») отримує **номер випуску** на 1
  більший. Мінімальний випуск типово дорівнює поточному. Клієнт і сервер мають
  бути з одного коміту (spec/клієнт-macos.md), тож старим клієнтом грати не
  дадуть, доки його не оновлять. Пом'якшити: `--min-release N`.
- Допублікувати платформу пізніше (наприклад, Mac з тієї ж збірки):
  `tools/opublikuvaty.sh macos`. Номер випуску не зміниться.
- Сервіс можна не зупиняти: публікація міняє теку платформи одним
  перейменуванням. Хто саме качав, отримає «хеш не зійшовся» і докачає ще раз.
- Сервер гри перезапусти з того самого коміту, з якого збірка.
- Апдейтер для гравців: `tools/zibraty_updater.sh` →
  `build/updater-<дата>-<коміт>/MyWay-Updater-<платформа>-….zip`.
  Його версія — `config/version` в `updater/project.godot` (ціле). Підняв її —
  у старих апдейтерів з'явиться жовте «є новіший апдейтер». Самі вони не
  оновлюються.
- Постійно: приклад юніта `tools/onovlennia/myway-updates.service`
  (systemd --user, не ввімкнено; як поставити — у ньому).

**Брандмауер** (ufw, вхідні DROP). Відкрити для домашньої мережі:

```
sudo ufw allow from 192.168.1.0/24 to any port 24600 proto tcp comment 'MyWay оновлення'
sudo ufw allow from 192.168.1.0/24 to any port 24565 proto udp comment 'MyWay гра'
```

## Сервіс оновлень

`tools/onovlennia/serve.py`: Python, лише стандартна бібліотека
(`ThreadingHTTPServer`). Python, а не Godot, тому що в Godot HTTP-сервера
немає. Довелось би розбирати HTTP на голому TCP, а Godot головою займає
сотні МБ. Тут HTTP, Range, потокова віддача й перевірка шляхів займають
сотню рядків без залежностей.

| Запит | Що віддає |
|---|---|
| `GET /config.json` | `name`, `game_port`, `protocol` (коміт), `client` {`release`, `version`, `commit`, `date`}, `min_client_release`, `updater_version`, `platforms` |
| `GET /manifest/<linux\|macos\|windows>.json` | `release`, `version`, `launch` (що запускати), `app` (Mac), `total`, `files`: [{`path`, `size`, `sha256`, `exec`}] |
| `GET /files/<платформа>/<шлях>` | файл; `Range: bytes=N-` → 206 (докачування), поза межами → 416 |

- Тільки GET і HEAD. Решта методів отримує 405.
- Усе поза цими трьома шляхами отримує 404.
- Шлях спершу розкодовується (`%2e%2e`). Потім відкидаються `..`, `.`,
  порожні сегменти, `\`, NUL і абсолютні шляхи. Наостанок `realpath` (він
  розкриває й посилання) має лежати всередині `files/<платформа>/`.
- Ключі JSON латиницею: це формат дроту між двома програмами.

## Апдейтер (`updater/`)

Окремий проєкт Godot 4.7 (GL Compatibility, бо йому досить кнопок). Пресети
експорту: Linux x86_64, macOS Universal, Windows x86_64. Дані вбудовано в
рушій.

- **Поле «IP сервера»** приймає `192.168.1.48` або `192.168.1.48:24610`;
  порт тут від сервісу оновлень, типовий 24600. Апдейтер питає `config.json`
  після Enter, «Перевірити» або 0,8 с паузи в наборі. Вдалу адресу він
  зберігає в `user://адреса.cfg` і на старті підставляє й перевіряє одразу.
- **Показує** назву сервера, адресу й порт гри, протокол, випуск на сервері
  й мінімальний випуск.
- **Звіряє** локальні файли з маніфестом за SHA-256. Кеш хешів за розміром і
  часом зміни (`.myway-hashes.json`) позбавляє від перерахунку 1,6 ГБ на
  кожному старті.
- **«Оновити»** качає лише те, що не збіглося. Кожен файл іде в
  `<файл>.part`; обірване докачується з `Range`. Потім перевіряється SHA-256,
  стара версія видаляється, `.part` перейменовується на місце, ставиться біт
  виконання. Якщо хеш не зійшовся, `.part` стирається. Перед завантаженням
  апдейтер перевіряє вільне місце, а на час оновлення стирає мітку
  встановленого випуску. Після оновлення прибирає все, чого немає в маніфесті.
- **«Грати»** викликає `OS.create_process(<launch>, ["--", "--host",
  "<IP>:<game_port>"])`. Кнопка заблокована, доки клієнта немає, доки йде
  оновлення, коли гру вже запущено і коли встановлений випуск менший за
  `min_client_release`. Причина видна в підказці й рядку під смугою.
- **Помилки** з'являються червоним текстом на екрані й у stdout. Окремі
  тексти є для таких випадків: сервер не відповів або відхилив з'єднання
  (з підказкою про `run-updates.sh` і брандмауер), адресу не знайдено, код
  відповіді, хеш не зійшовся, немає місця (скільки треба й скільки є),
  скінчилось місце посеред запису, файл зайнятий або немає прав, сервер
  замовк посеред файла, у маніфесті небезпечний шлях.

### Куди ставиться клієнт

У `user://client/<платформа>/` апдейтера (свій каталог, `custom_user_dir_name`):

| | |
|---|---|
| Linux | `~/.local/share/MyWay-Updater/client/linux/` |
| macOS | `~/Library/Application Support/MyWay-Updater/client/macos/MyWay.app` |
| Windows | `%APPDATA%\MyWay-Updater\client\windows\` |

Чому не поруч з апдейтером: на Mac `.app` апдейтера лежить у /Applications
або запускається з «транслокованої» копії лише для читання, а на Windows
може стояти в Program Files. У `user://` писати можна завжди. Чужу непорожню
теку апдейтер не чіпає: свою він позначає `.myway-client`. Для проб іншу теку
задає `-- --тека <шлях>`.

### macOS: підпис і `.pck`

Перевірено на збірці 26.11.2026 (cc57450):

- `.pck` лежить **усередині** бандла: `MyWay.app/Contents/Resources/MyWay.pck`.
  Печатка бандла (`_CodeSignature/CodeResources`) хешує кожен ресурс, тож
  будь-яка заміна `.pck` її ламає.
- Важливіше інше: вбудований у Godot підпис для клієнта **не вдається
  взагалі**. У журналі `macos.log` стоїть «CodeSign/CodeResources: Unsigned
  nested executable file», бо в GDExtension
  `Contents/Frameworks/libTree3D.macos.template_release.universal` зріз x86_64
  без підпису. Через це `_CodeSignature` у бандлі немає. Підпис лінкера мають
  рушій (обидва зрізи) і arm64-зріз бібліотеки, печатки ресурсів немає ні в
  кого.

**Рішення: підписати ad-hoc на місці, на Mac гравця.** Так найпростіше й
надійно. Після кожного оновлення апдейтер:

1. знімає `com.apple.quarantine` (`xattr -dr`). Godot сам карантин не ставить,
   це запобіжник;
2. запускає `codesign --verify --deep --strict`;
3. якщо печатка не сходиться, підписує кожен файл у `Contents/Frameworks`,
   потім бандл: `codesign --force -s -`. Потім перевіряє ще раз. `codesign` є
   в кожній macOS, Xcode не потрібен;
4. перепідпис змінює рушій і бібліотеки й додає `_CodeSignature/`. Тому для
   цих файлів кеш хешів отримує нові розмір і час, але хеш із маніфесту:
   «підписаний на місці файл маніфесту». Інакше наступна звірка вважала б їх
   зіпсованими й качала знову. `_CodeSignature/` прибирання не чіпає.

Не вдалось підписати? Апдейтер покаже червону пораду з командою для
Термінала, але грати не заборонить: arm64 з підписом лінкера зазвичай
запускається.

Варіант «`.pck` поза бандлом + `--main-pack`» відкинуто. Він не лікує
головного (печатки немає взагалі), а бандл без свого `.pck` не запуститься
подвійним клацанням.

**Не перевірено на справжньому Mac**: машини немає. Перше, що варто
перевірити: чи запускається `MyWay.app` після оновлення й чи проходить
`codesign --verify --deep --strict`.

Сам апдейтер (`MyWay Updater.app`) Godot підписує ad-hoc без помилок, бо
GDExtension у ньому немає. Гравцеві його однаково треба раз відкрити повз
Gatekeeper (ПКМ → «Відкрити», або `xattr -dr com.apple.quarantine`), як і
клієнт: spec/клієнт-macos.md, крок 2.

## Перевірка

```
updater/probe.sh                     # наскрізно на цьому ПК, без GPU, ~3 хв
LAN_IP=192.168.1.48 updater/probe.sh # і через LAN-адресу
godot --headless --path updater res://scenes/lint.tscn   # лінтер апдейтера
```

`probe.sh` усе піднімає на нетипових портах (HTTP 24600, гра UDP 24601;
24565 не чіпає) і все гасить у кінці. Піднімає:

- пробну публікацію в `build/.updater-probe.*` (не в `updates/`);
- сервіс оновлень;
- PostgREST, якщо він ще не працює;
- сервер гри зі світом 2 і базою;
- акаунт `test-upd-<час>`.

Сама проба `updater/probes/e2e.gd` проходить:

- розбір адреси й небезпечні шляхи;
- мертвий порт;
- config і порожню теку;
- обрив на 300 МБ і докачування з того байта;
- SHA-256 усіх файлів;
- заміну одного файла в публікації, після якої качається лише він;
- «хеш не зійшовся»;
- теку без права запису;
- LAN-IP;
- блок «Грати» за мінімальним випуском;
- «Грати»: клієнт `--headless` з `--host <IP>:24601` входить акаунтом і
  створює персонажа, і сервер друкує «приєднався».

Окремо curl перевіряє path traversal і Range у сервісу.

Не перевірено:

- Mac і Windows: машин немає. Збірки є, підпис апдейтера для Mac на місці;
- справжнє «скінчилось місце»: перевірка вільного місця є лише в коді;
- файл, зайнятий запущеною грою на Windows: на Linux замість нього
  перевірено теку без права запису.
