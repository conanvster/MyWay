# Як підняти базу

Postgres плюс PostgREST перед ним (рішення П-76 і П-92). Один раз.

Перевірено: Ubuntu 26.04, Godot 4.7.2. PostgREST у сховищах Ubuntu
**немає** — його беруть готовим бінарником із GitHub.

---

## 1. Postgres

```
sudo apt install -y postgresql
sudo -u postgres createdb myway
sudo -u postgres psql -d myway < db/schema.sql
```

> **Саме `<`, а не `-f`.** З `-f` файл читає користувач `postgres`, а
> домашній каталог йому закритий: `/home/alex` має права `drwxr-x---`, і
> виходить «psql: error: …/схема.sql: Відмовлено у доступі». Зі
> знаком `<` файл читає твоя оболонка — та, що вже має доступ, — і передає
> вміст готовим рядком. Перевірено 02.09.2026: перший спосіб упав, другий
> пройшов.

Схема створює `game.characters`, роль `game_api` (під нею ходить
PostgREST) і роль `game_anon` (її права й видно назовні). **Пароль у
`схема.sql` і в `postgrest.conf` замінити на свій** — там стоїть
`змінити-мене`.

### Якщо база вже стояла до кроку 4

Крок 4 додав два стовпці — `things` (поодинокі речі з афіксами) і `gear`
(що вдягнене). Без них запис падає з кодом 400:

```
sudo -u postgres psql -d myway < db/migration-step4.sql
```

### Якщо база вже стояла до складу (П-145)

Завідувач складу додав ще два стовпці — `warehouse_items` і
`warehouse_things`, друга пара до вже наявних `items`/`things`, тільки
для складу, не торби:

```
sudo -u postgres psql -d myway < db/migration-warehouse.sql
```

### Якщо база вже стояла до розподілу очок статів (П-147)

Новий стовпець `stats` — куди подіті очки за рівень (сила, спритність,
витривалість, інтелект, чуття):

```
sudo -u postgres psql -d myway < db/migration-stats.sql
```

### Якщо база вже стояла до розділення світів (П-204)

Персонажі стали свої в кожному світі: логін і пароль одні, а перелік
персонажів залежить від того, у якому світі стоїть сервер. Міграція
додає стовпець `world`, переносить **усіх наявних персонажів у світ 2**
(слово замовника 19.09.2026) і робить ім'я унікальним у межах світу, а
не на всю гру — тож первинним ключем стає пара `(name, world)`.

Заразом переписуються дві функції: `game.login` і `game.new_character`
беруть тепер ще один довід — світ. Старі підписи **видаляються**, а не
лишаються поруч: інакше PostgREST обирав би між двома однойменними
функціями за ключами тіла запиту, тобто мовчки й непередбачувано.

```
sudo -u postgres psql -d myway < db/migration-world.sql
```

Без неї гра піде, але сервер відповість кодом 404 на вхід: функції з
таким набором доводів у базі ще немає.

## 2. PostgREST

```
curl -L -o /tmp/postgrest.tar.xz \
  https://github.com/PostgREST/postgrest/releases/download/v16.2/postgrest-v16.2-linux-static-x86-64.tar.xz
mkdir -p ~/.local/bin && tar -xf /tmp/postgrest.tar.xz -C ~/.local/bin
./run-db.sh
```

> **В імені активу є версія, і без неї нічого не завантажиться.** Посилання
> виду `releases/latest/download/…` для PostgREST не працює: віддає
> дев'ять байтів «Not Found», і `tar` каже «Це не схоже на архів tar».
> Свіжу назву видно так:
> `curl -sL https://api.github.com/repos/PostgREST/postgrest/releases/latest | grep name`.
> Архітектура зветься `x86-64`, а не `x64` (`uname -m` покаже `x86_64`).

Перевірити, що все живе: `./run-db.sh --стан`.

## 3. Гра

```
./run-server.sh --база http://127.0.0.1:3000
./run.sh --run -- --персонаж Вовкодав
```

Сервер друкує, що знайшов:

```
[база] http://127.0.0.1:3000, зберігаю раз на 30 с
[база] Вовкодав повернувся: рівень 1, поваги 101
```

**Без `--база` гра працює як і раніше**, просто нічого не зберігає — і
каже про це першим же рядком: `[база] адреси немає — гра йде без
збереження`.

## Перевірено на справжньому Postgres

**02.09.2026**, Postgres 18 і PostgREST 16.2, два запуски поспіль:

```
перший:  [база] Вовкодав новий, починає з нуля
         у базі: рівень 1, повага 275, досвід 51, hp 55, mp 38, x -2,61
                 skills {"енергетичний-вибух": 1, "енергетичний-промінь": 1}
                 items  {"гроші": 46}

другий:  [база] Вовкодав повернувся: рівень 1, поваги 275
         загинув -> [смерть] втратив 100 поваги, лишилось 175
         у базі: повага 175, saved_at 14:03:16
```

Тобто підтверджено саме те, чого заглушка не покривала: **`jsonb`
приймає скіли й речі як є**, і **прав ролі `game_anon` вистачає** на
`INSERT` із `Prefer: resolution=merge-duplicates` — другий запис оновив
той самий рядок, а не додав новий.

## Як це було перевірено ДО того, як з'явилась база

`postgrest` тут не встановлено (потрібен пароль адміністратора), тому
клієнтську частину перевірено на **заглушці**, яка говорить тим самим
протоколом: `GET /characters?name=eq.Ім_я` і `POST /characters` із
заголовком `Prefer: resolution=merge-duplicates`.

Заміряно наскрізь, два запуски поспіль:

```
перший:  [база] http://127.0.0.1:3001, зберігаю раз на 30 с
         збережено: повага 101, досвід 22, речі {гроші 27, шкура 1},
                    скіли {вибух 1, промінь 1}, позиція x -0,37
другий:  [база] Вовкодав повернувся: рівень 1, поваги 101
         загинув -> [смерть] втратив 100 поваги, лишилось 1
         збережено знову: повага 1
```

Тобто гра справді зберігає, читає й накладає прочитане. Що лишається
перевірити на справжньому Postgres — тільки те, як він поводиться з
`jsonb` і чи вистачає прав ролі; сам протокол уже пройдено.
